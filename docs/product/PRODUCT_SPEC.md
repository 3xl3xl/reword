## 2. 目的と学習方針

### 決定事項・会話で共有された方向性

- 新しい難単語を大量に覚えることだけに偏らず、知っている語彙を正しい語順で使う。
- 100〜200個の基本文を、自分の生活に近い題材で自在に作れることを目指す。
- 生活・仕事・お金・ジム・旅行・恋愛など、本人に関係する内容を扱う。
- 短い反復セッションで、語彙の想起と英文づくりを続ける。

### 発展的な学習フロー（会話内の提案）

**ブロック選択 → 自力入力 → 声で言う → 似た文を自分で作る**

現在の具体的なUI要求はブロック選択・並べ替えと読み上げに集中しています。自由入力の採点、録音、音声認識、発音評価は未確認です。

## 4. UI / UX

### 4.1 確認できる画面要素

Sentence Blocksには、日本語の問題文、英語の選択肢ブロック、回答欄、Check、Next、右上の音ON/OFF操作が想定されています。選択肢をタップすると下の回答欄に並ぶ体験が会話で説明されています。

以下は要素の関係を示す概念図であり、実画面の復元ではありません。

```text
日本語の問題文                          音 ON/OFF

英語の選択肢ブロック
[I] [want] [to] [earn] [more] [money]
      ↓ 選択した場所には同サイズの空ブロックを残す

回答欄
[I] [want] ...  ← タップで戻す / ドラッグで並べ替え

[Check]
正解後：[                 Next                 ]
```

### 4.2 レイアウトと操作の決定事項

| 対象 | 要求 |
| --- | --- |
| 選択済みの元位置 | 詰めない。同サイズの文字なし・inactiveな背景を残す |
| 回答カード | サイズを揃え、複数行でも扱えるようにする。会話の実装方針は高さ固定 |
| ドラッグ中の挿入位置 | 周辺ブロックの間が滑らかに開き、挿入先が視認できる |
| 挿入判定 | 細かすぎる判定を改善し、広めの領域で左右の挿入を選べる |
| 正解後の主要操作 | Nextを単独・横幅いっぱいに広げ、押しやすくする |
| 音の操作 | 右上でON/OFFできる |

「回答カード」が回答欄全体か個々のブロックか、固定幅の有無、3行以上の扱いは未確認です。切り詰めやスクロールを既定仕様として断定しません。

### 4.3 未確認のビジュアル仕様

## 6. 保存語彙クイズ

### 6.1 定時クイズの決定事項

1. 開始時は接続済みRE:WORDの `start_quiz` を実際に呼ぶ。
2. 会話履歴だけを根拠に状態を推測しない。
3. 未完了なら再開し、`current.prompt` を **1問だけ** 提示する。
4. 回答を待つ。正解は先に見せない。
5. ユーザーが回答したら `get_quiz` で最新状態を確認する。
6. ユーザーが実際に回答した内容だけを `answer_quiz` で記録する。
7. 短く解説し、次の1問を提示する。完了ならその状態を伝える。

ツールの引数・状態名・レスポンス全体は不明です。上記は論理的な呼び出し順であり、実行可能なAPIサンプルではありません。

### 6.2 会話上の出題・採点例

- 日本語の意味から、保存した英語を答える問題。
- `idk` / 「わからん」に対して正解を示し、次へ進む例。
- 綴りの違う回答を不正解として扱った例。
- 3問のクイズ終了時に「3問中1問正解」と報告した例。
- 手動の語彙練習で、反対語や英語の意味を問う例。
- 別の埋め込み語彙クイズでは5問構成と5/5の結果への言及。

これらは複数の形式が混在した履歴です。**定時クイズを常に3問または5問に固定する決定は確認できません。** 自由な会話練習を `answer_quiz` に記録済みとも断定できません。

### 6.3 境界条件

| 状態 | 要求される対応 |
| --- | --- |
| 未完了のクイズあり | 実際の状態を確認して再開する |
| 対象なし | 対象がないことを明示する |
| 同じ時間帯のクイズが完了済み | 完了済みと伝え、存在しない追加問題を作らない |
| 接続失敗・ユーザー入力が必要 | 開始できなかった事実を伝え、問題や回答を捏造しない |
| 回答前に状態が変化 | 最新状態を優先する。照合方法・再確認UIは要設計 |

同じ時間帯の完了後に「もっと問題」が求められた場合、追加練習を別セッションで認めるかは未決定です。履歴には完了済みの案内後に自由練習を出した例もあり、定時クイズとの境界を整理する必要があります。

## 8. Sentence Blocks

### 8.1 基本構成

**決定事項：5問を1つの連続した流れにする。** 日本語に対応する英文を、英単語またはフレーズのブロックを並べて作ります。

会話内の教材例：

```text
日本語：私はもっとお金を稼ぎたい
ブロック：I / want / to / earn / more / money
完成文：I want to earn more money.
```

別の例では `to Europe` / `next year` が1ブロックになっています。単語単位だけでなくフレーズ単位の分割も想定されています。初期シャッフルや余分な選択肢の有無は未確認です。

### 8.2 タップ操作

1. 選択肢ブロックをタップすると回答欄へ追加する。
2. 選択した英語を読み上げる。
3. 元位置には同サイズの文字なし・非アクティブな背景を残す。
4. 回答欄のブロックをタップすると選択を取り消して戻せる。

戻すときの読み上げや、ドラッグで移動したときの再読み上げは未決定です。

### 8.3 ドラッグ＆ドロップ

- 回答欄に追加済みのブロックをドラッグして並べ替えられる。
- 挿入予定位置に滑らかな隙間を作る。
- どの2つのブロックの間へ入るかを明確にする。
- 挿入判定を広めに取り、少しの移動で候補が過敏に切り替わる挙動を改善する。

元の選択肢から回答欄へのドラッグ追加は、明示された要件ではありません。タップで追加し、回答欄内をドラッグで並べ替える仕様が確認できます。

### 8.4 CheckとNext

| 状態・操作 | 確認できる仕様 |
| --- | --- |
| Checkを押す | 組み立てた文を判定する |
| 正解 | 正解音と完成した英文の読み上げ。Nextを単独・全幅で表示 |
| 不正解 | 不正解音を追加する方針 |
| Next | 5問の流れの次の問題へ進む |

不正解時のヒント・正解表示・再試行回数、未完成時のCheckの有効性、最終問題後の画面、スコアの計算方法は未確認です。

## 10. 音声・効果音

### 決定事項・会話で示された方針

- ブロック選択時、その英語を男性音声で読み上げる。
- Checkで正解したとき、完成した英文を最初から読み上げる。
- 選択音・正解音・不正解音を追加する。
- 右上の操作で音をON/OFFできる。
- できるだけ自然な、ネイティブらしい男性声を希望する。
- 会話内の代替方針は、端末で利用できる英語音声から自然な男性声を優先すること。

会話ではChatGPTのSpruceのような声をそのUIから直接呼べないと説明されています。本書は、その説明を当時の環境上の制約として記録しています。利用可能な音声サービス全般の制約を断定するものではありません。

### 技術的な注意点（実装・検証の提案）

- 端末・ブラウザによって利用可能な音声が異なるため、希望する声がない場合の代替を用意する。
- 音声を使えない状態でも、選択・判定・Nextを操作できるようにする。
- 連続タップ時の読み上げの重複、待ち行列、キャンセル方針を決める。
- 問題を切り替えた後に古い文が読み上げられないようにする。
- 音ON/OFFが効果音と読み上げの両方に適用されるか、設定が保存されるかを決める。

使用API、音声提供元、速度、音量、アクセント、効果音素材、音声キャッシュは未確認です。

## 11. 技術設計上の注意点

以下は確定した実装ではなく、要求を安定して満たすための提案です。

### 状態の管理

- 保存語彙クイズでは、会話履歴よりRE:WORDの最新状態を優先する。
- 回答を送信するときは対象セッション・問題との対応を確認し、重複送信を防ぐ。
- Sentence Blocksでは、同じ文字列のブロックが複数あっても別々に扱える識別子を使う。例文には `to` が複数登場する。
- 選択肢の元位置、選択済み状態、回答欄の順序を分けて管理する。

### レイアウトと入力

- 改行を含む回答欄で、ドラッグの挿入先を行の位置も含めて判断する。
- ドラッグとタップ取り消しが同時に発生しないようにする。
- 先頭・末尾への挿入、キャンセル、範囲外へのドロップの挙動を決める。
- 固定サイズと長い文の両立を、実際の狭い画面で確認する。
- キーボード操作、フォーカス表示、読み上げラベル、動きを減らす設定を検討する。

### 採点

- 語順完全一致か、意味が同じ別の語順も認めるかを決める。
- 大文字小文字、句読点、短縮形、綴り違いの許容範囲を決める。
